TOPIC 1: RELATIONAL DATABASE DESIGN AND STRUCTURE
============================================================

Coach: Let us start with the database design. Which tables are involved in the service-project and category features, and what relationship must the database support?

Student: The main tables are organization, service_project, category, and project_category. Each service project belongs to one organization, so service_project has an organization_id foreign key. Projects and categories have a many-to-many relationship: one project can have more than one category, and one category can be assigned to more than one project. The project_category table is the junction table that stores those associations.

Coach: Please share a non-trivial SQL snippet that shows how you modeled the category relationship, and explain the constraints.

Student: This is from src/setup.sql:

CREATE TABLE category (
    category_id SERIAL PRIMARY KEY,
    name VARCHAR(100) NOT NULL UNIQUE
);

CREATE TABLE project_category (
    project_id INTEGER NOT NULL,
    category_id INTEGER NOT NULL,
    PRIMARY KEY (project_id, category_id),
    CONSTRAINT project_category_project_fk
        FOREIGN KEY (project_id)
        REFERENCES service_project (project_id)
        ON DELETE CASCADE
        ON UPDATE CASCADE,
    CONSTRAINT project_category_category_fk
        FOREIGN KEY (category_id)
        REFERENCES category (category_id)
        ON DELETE CASCADE
        ON UPDATE CASCADE
);

The category table has a unique ID and a unique name. The project_category table has two foreign keys, one to service_project and one to category. Its composite primary key prevents the same project and category from being associated more than once. The foreign keys prevent invalid IDs from being inserted. The cascade behavior removes relationship rows when their related project or category is deleted.

Coach: Why did you use a junction table instead of putting one category_id column directly in service_project?

Student: A single category_id column would allow only one category for each project. That would not satisfy the requirement that a project can belong to one or more categories. The junction table allows multiple rows for one project and also allows one category to be used by many projects. It is the correct normalized design for a many-to-many relationship.

Coach: Show one relevant SQL statement that associates existing projects with categories. What does it do?

Student: One example from src/setup.sql is:

INSERT INTO project_category (project_id, category_id)
SELECT service_project.project_id, category.category_id
FROM service_project
CROSS JOIN category
WHERE category.name = 'Food Security'
  AND service_project.title IN (
      'Community Food Harvest',
      'Community Food Drive',
      'Holiday Giving Project'
  );

This looks up the IDs using the names, then inserts the associations for the matching projects. It avoids hard-coding numeric IDs. The foreign keys make sure that the selected project and category rows exist.

Coach: How did you verify that every project was associated with at least one category?

Student: I used a query that counts projects for which no matching project_category row exists:

SELECT COUNT(*) AS projects_without_categories
FROM service_project
WHERE NOT EXISTS (
    SELECT 1
    FROM project_category
    WHERE project_category.project_id = service_project.project_id
);

The result was zero. The database contained four categories and twenty-one project-category associations, and every service project had at least one category.

TOPIC 2: SERVER-SIDE DATA ACCESS LOGIC IN NODE.JS
============================================================

Coach: Now let us follow the data after it leaves PostgreSQL. Which file contains the category database function, and what does that function return?

Student: The function is in src/models/categories.js. It returns result.rows, which is an array of category objects from the database. Each object contains category_id and name.

Coach: Please share the complete function and explain the flow line by line.

Student: The function is:

import db from './db.js';

const getAllCategories = async () => {
    const query = `
        SELECT category_id, name
        FROM category
        ORDER BY name;
    `;

    const result = await db.query(query);

    return result.rows;
};

export { getAllCategories };

The db import is the shared PostgreSQL connection from the database model. getAllCategories is asynchronous because a database query takes time and returns a promise. The query selects the category ID and name, and ORDER BY name sorts the rows alphabetically. await db.query(query) waits for PostgreSQL to return the result. The result object contains metadata and the rows. Returning result.rows gives the route only the records it needs for rendering. The export makes the function available to server.js.

Coach: Why is the query in src/models/categories.js instead of directly inside server.js?

Student: Separating the query into a model keeps responsibilities organized. The model handles database access, while server.js handles HTTP routes and rendering. This makes the code easier to read, test, reuse, and maintain. It also follows the same naming and file pattern used for getAllOrganizations and getAllProjects.

Coach: How does the project query differ from the category query?

Student: The project query uses a JOIN because each project must display the sponsoring organization name. It selects project fields and organization.name AS organization_name. The category query does not need a join because the categories page only displays category names.

Relevant project-query example from src/models/projects.js:

const getAllProjects = async () => {
    const query = `
        SELECT
            service_project.project_id,
            service_project.title,
            service_project.description,
            service_project.project_date,
            organization.name AS organization_name
        FROM service_project
        JOIN organization
            ON service_project.organization_id = organization.organization_id
        ORDER BY service_project.project_date;
    `;

    const result = await db.query(query);

    return result.rows;
};

Student: The JOIN connects each project to its organization through organization_id. This lets the EJS page display the organization name without making a separate query for every project.

TOPIC 3: EXPRESS SERVER LOGIC AND ROUTING
============================================================

Coach: How does Express know which code should run when a user visits the categories page?

Student: Express matches the HTTP method and URL path to a route declaration. A browser visit to /categories sends a GET request, so Express uses app.get('/categories', ...). The function receives the request and response objects. The handler gets the data, sets the title, and renders the categories view.

Coach: Please share the specific route declaration from server.js and explain each important part.

Student: The route is:

app.get('/categories', async (req, res) => {
    const categories = await getAllCategories();
    const title = 'Service Project Categories';
    res.render('categories', { title, categories });
});

app.get registers a handler for GET requests. The path /categories is the URL path. The async keyword is necessary because getAllCategories returns a promise. await pauses the handler until the database rows are available. The rows are stored in categories. res.render tells Express to render categories.ejs and passes title and categories as template data.

Coach: What would happen if the route called getAllCategories but did not pass categories to res.render?

Student: The EJS template would not receive the categories variable. When it tried to run categories.forEach, it would likely produce an error because categories would be undefined. Passing the data object is the connection between the route and the template.

Coach: How are the organizations and projects routes similar?

Student: They use the same pattern. The organizations route awaits getAllOrganizations and renders organizations.ejs with title and organizations. The projects route awaits getAllProjects and renders projects.ejs with title and projects. The route handlers map URLs to the correct model and view.

Relevant projects route:

app.get('/projects', async (req, res) => {
    const projects = await getAllProjects();
    const title = 'Service Projects';
    res.render('projects', { title, projects });
});

Student: This route makes the projects page dynamic. It retrieves the database rows first, then sends them to the EJS template rather than rendering the old hard-coded list.

TOPIC 4: CLIENT-SIDE DISPLAY USING EJS TEMPLATES
============================================================

Coach: How does the data passed from Express become visible HTML in the browser?

Student: EJS is the template engine. Express passes the database data into the EJS view. EJS evaluates the JavaScript template tags on the server and creates normal HTML. The browser receives the generated HTML, not the EJS code itself.

Coach: Please share a specific EJS snippet that loops through the database categories and displays each name.

Student: The relevant code in src/views/categories.ejs is:

<% categories.forEach(category => { %>
    <li><strong><%= category.name %></strong></li>
<% }) %>

The <% tags run JavaScript without directly outputting it. The forEach loop processes every object in the categories array. For each object, it creates one li element. The <%= category.name %> tag outputs the name and escapes it as HTML. Therefore, database categories become visible list items.

Coach: What is the difference between <%= ... %> and <%- ... %> in this project?

Student: <%= ... %> outputs a value and escapes HTML characters, so it is appropriate for database text such as category.name, project.title, and organization_name. <%- ... %> outputs unescaped HTML. The project uses it for trusted partial includes such as <%- include('partials/header') %> and <%- include('partials/footer') %>, because those partials contain HTML markup that must be interpreted as HTML instead of displayed as text.

Coach: Share the project EJS snippet and explain how the date and organization are displayed.

Student: The projects view uses:

<% projects.forEach(project => { %>
    <li>
        <%= new Date(project.project_date).toLocaleDateString('en-US', {
            year: 'numeric',
            month: 'long',
            day: 'numeric'
        }) %>:
        <strong><%= project.title %></strong>
        (<%= project.organization_name %>)
        <p><%= project.description %></p>
    </li>
<% }) %>

The loop creates one list item per project. The date is converted into a JavaScript Date and formatted in a user-friendly month-day-year style. The project title, organization name, and description come from the SQL query and are displayed with escaped EJS output tags.
